# DEC-36 – Frammento Must B «Smistare» e cartelle sul file system

**Data:** 2026-09-28 · **Stato:** Superata da DEC-48 (solo le cartelle sul disco) · **Idea di origine:** —

## Contesto
Chiuso il frammento Must A (scrivere), il passo successivo è organizzare le note: spostare le non organizzate nelle cartelle (FL-05). Restavano da scegliere il perimetro del frammento e dove vivono le cartelle, visto che le note sono file markdown in una cartella del disco, soluzione provvisoria (DEC-29).

## Opzioni valutate
Perimetro: A) solo cartelle e trascinamento; B) anche il cestino; C) anche «Sposta in» dal menu `···` della nota.
Cartelle: A) sottocartelle vere del file system, con lo stesso nome; B) database definitivo sul dispositivo subito.

## Decisione
Scelte di Manuel Cucca:
- Nasce il frammento **Must B · Smistare**: cartelle (RF-05) con creazione, rinomina e spostamento anche per trascinamento, **cestino** (RF-15) e **«Sposta in»** dal menu `···` della nota aperta.
- Le cartelle sono **sottocartelle vere** di Documenti\Memodu, come le note sono file (DEC-29). Il nome della cartella in Memodu e quello sul disco sono **lo stesso**.
- Anche questa è una soluzione **provvisoria**: con ogni probabilità si passerà al database definitivo sul dispositivo (rinvio di DEC-29).

## Conseguenze
- `docs/avanzamento.md`: nuovo frammento Must B.
- I nomi delle cartelle sono vincolati dalle regole del file system (caratteri vietati, lunghezza): regola da decidere.
- Da decidere anche: dove sta il cestino sul disco, comandi del server per cartelle e cestino, ordine di cartelle e note, «Unisci» con sottocartelle omonime, nota aperta spostata.
- Il menu `···` di SC-03 entra nel codice solo con le voci del frammento (Sposta in…, Elimina); le altre (Tag…, Date…) arrivano con i loro requisiti.
